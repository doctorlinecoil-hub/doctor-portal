# מערכת תורים ומכתבים – ד״ר אלרן חנוך

משרדי עורכי דין קובעים תור, מעלים מסמכים וכותבים מה הם צריכים.
הרופא רואה את היומן, פותח תיק, מקבל טיוטת מכתב מ-AI לפי המסמכים, מתקן, מדפיס ל-PDF ושולח למשרד.

## מה יש בפנים
- **כניסה:** אימייל וסיסמה. משתמשים חדשים מקבלים סיסמה זמנית ומחליפים אותה בכניסה הראשונה.
- **אימות דו-שלבי:** חובה לרופא ולמנהל, עם קוד מאפליקציה בטלפון.
- **הפרדה בין משרדים:** כל משרד רואה רק את התיקים שלו. האכיפה נעשית במאגר הנתונים עצמו (Row Level Security), לא רק במסכים.
- **תורים:** לפי זמני הקבלה בהגדרות. אי אפשר לקבוע שני תורים חופפים.
- **מסמכים:** נשמרים באחסון פרטי. נפתחים רק דרך קישור זמני של שעה.
- **AI:** ניסוח טיוטה דרך Claude API. המכתב הסופי יוצא רק אחרי שהרופא אישר אותו.
- **יומן פעולות:** מתועד מי קבע תור, מי העלה מסמך, מי צפה בתיק, מי סיים מכתב ומי רשם תשלום.
- **מפנים:** משרדי עורכי דין ומתווכים, כל אחד עם משתמשים משלו.
- **תשלומים:** מחיר לכל סוג תיק, מי משלם (המפנה או המטופל), רישום תשלומים, יתרות ומסך גבייה.
- **חשבוניות:** הפקת חשבונית מס / קבלה במורנינג (חשבונית ירוקה) ישירות מהתיק, או רישום מספר קבלה ידני.
- **מכתב אחרי תשלום (אופציונלי):** המכתב הסופי נפתח למפנה רק אחרי תשלום מלא.
- **אישור תורים:** תור שהמפנה קובע נכנס כבקשה. הרופא מאשר או דוחה, מהלוח הראשי או מתוך התיק.
- **זימונים במייל:** אחרי האישור נשלח זימון מעוצב למפנה ולמטופל (אם הוזן מייל), עם קובץ "הוספה ליומן", ניווט ב־Waze ורשימת "מה להביא". אם לא הוזן מייל של המטופל, הזימון נשלח למפנה כדי שיעביר אותו.
- **תזכורת:** יום לפני התור, אוטומטית.
- **המכתב הסופי במייל:** כשהרופא מסמן את המכתב כסופי, הוא נשלח כ־PDF למפנה ולמטופל. אם נדרש תשלום, המכתב יוצא לבד מיד כשהתשלום נרשם.
- **סריקת AI לכל פנייה:** Claude קורא את כל המסמכים ומכין לרופא סיכום, ציר זמן רפואי, אבחנות ובדיקות, דגלים אדומים, אי־התאמות בפרטי המטופל, מה לבדוק בביקור ואחוז שלמות התיק.
- **בקשת השלמות:** מרשימת המסמכים החסרים הרופא שולח בלחיצה בקשה למפנה. הבקשה מופיעה אצל המפנה בתיק ונשלחת אליו גם במייל. כשהמפנה מעלה מסמכים, הרופא מקבל הודעה והתיק נסרק מחדש.
- **וואטסאפ בלחיצה:** כפתורים שפותחים וואטסאפ עם הודעה מוכנה (זימון, תזכורת, "המכתב מוכן"), בלי חשבון עסקי.

## טכנולוגיה
Next.js 15 · Supabase (Postgres, Auth, Storage) · Claude API · Vercel

## משתני סביבה
ראו `.env.example`. משתני Supabase מתמלאים לבד כשמחברים את Supabase דרך Vercel.

| משתנה | מה זה |
|---|---|
| `ANTHROPIC_API_KEY` | מפתח ה-AI מ-console.anthropic.com |
| `ANTHROPIC_MODEL` | לא חובה. ברירת המחדל: `claude-opus-5-5` |
| `SETUP_CODE` | קוד חד-פעמי ליצירת המנהל הראשון בכתובת `/setup` |
| `MORNING_API_KEY_ID`, `MORNING_API_KEY_SECRET` | לא חובה. מפתחות API של מורנינג להפקת חשבוניות |
| `MORNING_ENV` | לא חובה. `sandbox` לבדיקות מול סביבת הניסוי של מורנינג |
| `RESEND_API_KEY` | מפתח של Resend לשליחת מיילים (חינם עד 3,000 בחודש) |
| `MAIL_FROM` | השולח, למשל `מרפאת ד״ר אלרן חנוך <clinic@doctorline.co.il>`. צריך לאמת את הדומיין ב־Resend |
| `MAIL_REPLY_TO` | לא חובה. לאן יגיעו תשובות למיילים |
| `APP_URL` | כתובת המערכת, לקישורים במיילים |
| `CRON_SECRET` | טקסט אקראי ארוך. מגן על משימת התזכורות היומית (`vercel.json`) |

## התקנה (בקצרה)
1. מעלים את הקוד ל-GitHub (מאגר פרטי).
2. ב-Vercel מייבאים את המאגר, ומוסיפים Supabase דרך Storage → Supabase (אזור: Frankfurt).
3. מוסיפים את `ANTHROPIC_API_KEY` ואת `SETUP_CODE`, ופורסים. מבנה המאגר נוצר לבד בזמן הבנייה (`scripts/migrate.mjs`).
4. ב-Supabase: Authentication → כיבוי "Allow new users to sign up".
5. נכנסים ל-`/setup`, יוצרים מנהל, ומוסיפים את הרופא ואת המשרדים במסך "משרדים ומשתמשים".
6. מחברים כתובת, למשל `portal.doctorline.co.il`, ב-Vercel → Domains.
